# SUMO Microscopic Traffic Simulation Suite (CC-HLP Preemption)
### Microscopic Validation via Eclipse SUMO & TraCI (Traffic Control Interface)

This directory contains the formal **SUMO (Simulation of Urban MObility)** configuration and TraCI control scripts for the **CC-HLP (Chance-Constrained Human-in-the-Loop Emergency Vehicle Preemption)** research project.

---

## 1. Role of SUMO in Our Project Architecture

In academic transportation research and patent specifications, validation follows a **Two-Tier Architecture**:

```
+-----------------------------------------------------------------------------------+
|                           TIER 1: SCIENTIFIC BENCHMARK                           |
|                               (Eclipse SUMO & TraCI)                             |
|  - Microscopic vehicle car-following (Intelligent Driver Model - IDM)              |
|  - Sub-second trajectory integration (100ms time-step)                            |
|  - 50-seed Monte Carlo batch evaluation across baseline comparator controllers    |
+-----------------------------------------------------------------------------------+
                                        |
                                        v
+-----------------------------------------------------------------------------------+
|                        TIER 2: CYBER-PHYSICAL DIGITAL TWIN                        |
|                              (WebGL / Three.js Engine)                            |
|  - Real-time 3D interactive corridor visualization                                |
|  - NEMA TS2 Hardware Cabinet (MMU-16LE conflict monitor, BIU SDLC bus)            |
|  - 5.9 GHz C-V2X radio & 800ms fail-safe hardware watchdog simulation             |
+-----------------------------------------------------------------------------------+
```

1. **Tier 1 (SUMO + TraCI)**: Runs batch Monte Carlo evaluations without rendering overhead to compute statistical guarantees ($P(T_{\text{clear}} \le \text{ETA}) \ge 1 - \epsilon$) and compare against baselines (Fixed 300m trigger, Obrusnik Queue-Discharge).
2. **Tier 2 (3D Digital Twin)**: Provides the interactive, visual digital twin used for live stakeholder demonstrations and hardware cabinet fault injection.

## 2. Directory Structure

| File | Purpose |
| :--- | :--- |
| `corridor.nod.xml` | Geometric node definitions (West entrance, signalized intersection, East exit, Cross streets). |
| `corridor.edg.xml` | Edge definitions: 2-lane arterial mainline (72 km/h) and 1-lane cross street (50 km/h). |
| `corridor.net.xml` | Compiled traffic network with signalized junction and NEMA 4-phase traffic light logic. |
| `corridor.rou.xml` | IDM car-following vehicle definitions, queued traffic, moving traffic, and priority ambulance. |
| `corridor.sumocfg` | Master SUMO configuration file with 0.1s step resolution and lateral sub-lane physics. |
| `run_cchlp_traci.py` | TraCI Python controller executing the Dual-Action Law, dynamic zipper merging, and watchdog logging. |
| `sumo_cchlp_benchmark_output.csv` | Output comparison metrics generated by the TraCI controller. |

## 3. How to Run the Simulation

### Option A: Direct Python Execution (Runs on any machine immediately)
The controller script includes a native kinematic fallback engine that mirrors SUMO physics:
```bash
python3 sumo_simulation/run_cchlp_traci.py
```
This runs both the **Proposed CC-HLP Dual-Action Controller** and the **Baseline Static 300m Trigger**, printing step-by-step logs and exporting `sumo_cchlp_benchmark_output.csv`.

### Option B: Visual GUI Run with Eclipse SUMO
To view the simulation in the official SUMO graphical environment:
1. Install SUMO:
   ```bash
   brew install sumo    # macOS
   sudo apt install sumo sumo-tools sumo-gui    # Ubuntu/Debian
   ```
2. Launch the scenario in SUMO GUI:
   ```bash
   sumo-gui -c sumo_simulation/corridor.sumocfg
   ```
3. Connect the TraCI controller:
   ```bash
   python3 sumo_simulation/run_cchlp_traci.py --traci
   ```

## 4. Key Metrics Measured

1. **Ambulance Transit Time ($T_{\text{transit}}$)**: Time from corridor entry to passing the stopline.
2. **Emergency Braking Episodes ($N_{\text{brake}}$)**: Count of deceleration events where $a < -2.5\,\text{m/s}^2$.
3. **Complete Stops**: Instances where ambulance speed dropped to $0\,\text{m/s}$ due to queue blockage.
4. **Clearance Buffer Violations**: Safety violations where inter-vehicle clearance dropped below $5.0\,\text{m}$.
5. **Cross-Street Transient Delay**: Webster 3-cycle queue delay experienced by non-emergency vehicles.
